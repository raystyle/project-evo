# ADR-0010:市场更名 project-evo 与四插件形态,dev-evo 与 super-research 各拆细

## Context

v0.7.0 封版后用户裁定品牌统一:本地仓目录已改 project-evo,市场名 projectevo 与 GitHub 仓 raystyle/projectevo 一并改齐。单插件五 skill 形态(ADR-0001)职责域过宽:文档治理、代码安全、研究检索、多仓协作四域的负载与演进节奏不同,单插件内一个 skill 变更牵动整插件版本。dev-evo 单 skill 同时承载知识面(合同/ADR/REQ/投影/六态)与工具面(骨架脚本/模板/门禁),意图路由天然分缝。super-research 的成文产出面可吸收家族研究仓的报告生成实践(md 唯一真源、md/pdf/docx 三件套、Typst 渲染、版式复检、断言对照、信源存档、索引登记)沉淀为可复用 skill。

## Decision

- 市场名 projectevo 改 project-evo,GitHub 仓同步改名 raystyle/project-evo(旧地址重定向兼容);ADR-0001 单插件形态整体 supersede
- 四插件分域:evo-adr(doc-gov 文档治理知识 + code-kit 骨架与门禁工具)、evo-codesec(secret-scan + security-audit)、evo-research(research 检索管线 + report 研究成文)、evo-herdr(herdr-flywheel)
- dev-evo 按意图路由拆细:references 17 篇按知识面(9 篇进 doc-gov)与工具面(8 篇进 code-kit)分家,五脚本、assets/templates 与 verification 归 code-kit;ADR-0007 的 17 篇参考边界总量不变(构成重分),ADR-0009 的五 skill 同插件条款改为分插件归属;ADR-0004 的 diary/research 档案条款由 doc-gov 承载
- super-research 拆 research(发现/获取/研读)与 report(研究成文三件套);report 按仓规「吸收即提炼」吸收家族研究仓实践,成品不点名外部仓;docx 渲染(python-docx + OfficeCLI)与版式复检(pillow/pypdfium2)带外部依赖,不合脚本零依赖惯例,以 references 知识形态承载,脚本面仅收零依赖 render.py(参数化项目根;typst 定位只认 --typst/TYPST/PATH 三选一,跨平台命令分发由宿主工具链统一维护,脚本不烙死机器路径)
- 四插件同版本线,自 0.1.0 起;浅扫(md 禁字门禁)留 code-kit、深扫留 secret-scan 的既有边界不变
- 各 skill 依赖的外部命令(gh、bh、reader、aria2c、typst 等)全平台分发安装由宿主工具链 omc 与 ark 统一维护:skill 只认 PATH(或等价显式指定,如 render.py 的 --typst/TYPST),不内置安装路径与机器回退
- 新写与改写 SKILL.md 统一构造纪律:命令块实证准入(写进去的命令本会话真跑过)、脚本即交付物(SKILL.md 是 man page)、一条活路、坑出实碰、description 动词化;方法论参考 run-skill-generator,与仓内六态实证口径同源

## Consequences

- 好:四域各自演进互不牵动版本,市场消费者按域安装;dev-evo 知识/工具分面后两份 SKILL 更短更准;报告生成能力从个人仓沉淀为可复用 skill
- 坏:manifest 面从两份涨到八份(双面乘四插件),守卫测试复杂度上升;跨插件引用(路由行、ab.py 交叉路径)须带插件归属维护
- 升级破坏性:旧市场 projectevo 的客户端缓存滞留须卸旧装新;斜杠前缀 /project-evo:* 全部变为 /evo-adr:*、/evo-codesec:* 等,CHANGELOG 记破坏性说明
