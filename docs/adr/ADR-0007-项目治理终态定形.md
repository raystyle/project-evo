# ADR-0007:项目治理终态定形

## Context

herdr 飞轮四类轮次(对齐、标准态、终态、扩编与讨论)跑完,六仓(ark_rs、hst_rs、ohmycloud、reader_rs、browse-rs、clean-chrome)全部按 v0.6.0 加第五十七至六十一批增量对齐落地并回执核验。用户 2026-09-16 裁定:项目治理终态就此确定。

## Decision

插件定位定调(用户 2026-09-16):ProjectEvo 四 skill 同属**项目治理面**,非业务工具面:dev-evo 文档体系治理、super-research 资料检索治理、secret-scan 密钥隐私治理、security-audit 安全审计治理。dev-evo 终态 = 五件套:ADR 与 REQ 治理体系、diary 与 research 档案机制(ADR-0004 红线)、三栈文档即代码标准与工具(Rust aidoc 强制 ADR-0006、契约注释纪律、Python/TS 工程合同)、agent CLI 三栈标准(发现通道、输出信封、CTA、三栈落位)、AGENTS 五节合同与 17 篇参考边界(第六十一批收敛,env-environment、flow-events、tool-selection 退役)。后续改动终态任一面(增删参考、改强制项、动档案结构)须立新 ADR 显式 supersede,不走静默演化。

## Consequences

- 好:终态有决策锚,飞轮各仓对齐目标面冻结,后续批次只需增量不需再议形态;扩张走显式决策留痕
- 坏:形态变更门槛变高(每动终态面立 ADR);家族外第三方仓按此终态采用时,五件套为全量起点,无裁剪版(可后续按反馈评估分级形态) [假设]
