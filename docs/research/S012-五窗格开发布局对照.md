# S012:PI 智能体五窗格开发布局对照

> 信源:pi-rs 仓 CLAUDE.md(herdr 委派开发方式,四路开发模型与布局定式;2026-10 快照)。对照对象:本仓 evo-herdr:herdr-flywheel 与 herdr-review。用户裁定(2026-10-07):五窗格仅 PI 智能体开发模式适用;通用项目四窗格足够,自省位可替换为 codex。信源点名止于本档案。

## 布局定式:用户裁定后的标准形

**通用四窗格(主窗口同 tab 四格)**:

| 窗格 | 角色 | 委派面 |
| --- | --- | --- |
| 主开发格 | 主编程及调度委派(claude code) | 总台本体;派单与收批 |
| 研究格 | 研究(grok 等) | 资料与选型检索派单 |
| review 格 | 评审(kimi、grok 等) | 推送前评审闸门(herdr-review 口径) |
| 自省回归格 | 自省验收(codex;PI 项目用 pi 本体) | 清单式实测回归,逐项 过/缺 加证据 |

**PI 智能体开发模式特化(五窗格)**:自省回归位用被测产品自身(pi 用 pi 验证 pi);另开副窗 table 格做实战验收(长跑解题会话,与自省格是两个独立会话)。

## 上游实践要点:吸收源

- 双闸门收批:review CONFIRM 加自省验收全过,双绿才收;有 F/缺修后重推复审循环到零
- 先推后审:评审只认已推送的树,派单前 commit 加 push
- 自省会话纪律:自省格上下文近满(约八成)重启会话再派;实战格保持长会话,近满让自动压缩接管(压缩表现本身就是被测面),压缩后失能才重启并记档
- 重载铁律:项目代码落地后自省与实战两格必重启会话重载(旧进程等于旧码);派验收前确认格上跑的是当前 HEAD
- TUI 就绪探测:新会话先 pane wait-output 等就绪标志再派(未就绪时 send-text 悬输入框);普通进程脚本用 send-text 加 send-keys enter 两步起
- 运行时坑:首跑偶发执行器 cwd 瞬时错,重跑即过
- 派单地址以 herdr agent list 实查为准(与本仓口径同源,互证)

## 对照分流

- 等价不吸收:事件驱动禁 sleep 轮询、状态门控、租约与防重发、send-text 不作派单通道、评审方陈述不作数(与本仓 flywheel 及 review 口径同源,pi-rs 属下游反哺互证)
- 真新增吸收:四窗格通用定式与 PI 五窗格特化、双闸门收批(review 加自省验收)、先推后审、自省与实战会话纪律(近满重启与长会话压缩)、重载铁律、TUI 就绪探测
- 留档:pi-rs 件契约与归档分层等产品面细节(非 herdr 布局面)
