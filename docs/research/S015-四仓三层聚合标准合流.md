# S015:四仓三层聚合标准合流

## 背景

用户立单(2026-10-10,八条裁定递进):sources 层与 doc-gov 面统一;四仓达成一致对齐修成一个标准;比标准更好的实践回流改进标准;ai-ccoe 文档目录乱点五处先正名;归档统一(字母表);doc-gov 对齐 Rust 治理实践;代码即文档三语言;三层知识项目级自持不设跨仓共享库。三实践仓当时已各自长出三形态:ai-ccoe 仓根三层单仓提交分层、pve-harness docs 中心全家桶单仓路径级回滚(其 ADR-0007 用户裁定)、browse_rs 未建以 diary 等价形在主仓。

## 关键结论,逐条六态

1. [实证] 同标准三种解是常态:三仓词汇趋同(ADR/REQ/R/G/M/P/S/diary)而归位互异,pve R002 与 ai-ccoe G003 同题异前缀;归档统一靠字母表定死归层,不靠目录位置强同。
2. [实证] 业界八例中四件是我们独有:合取闸门拒均值(要变好不是不变坏)、防重提页加 no_action 出口、relation 两根词资格判据加禁跨仓共享库、标准页头三证据加投影漂移退出码;均验证为判例价值,非缺口。
3. [实证] WikiSkill 论文与 distil-skill 同构(distil-skill 即其治理变体,承 S014);其分叉三件已吸收:执行回合不读知识层(论文 5.1:默认配置执行者不读 wiki 63.7%,执行者也读 wiki 降至 60.9%)、技能指回模式页(PURPOSE.md 形)、原地补丁为负例(否证走 supersede)。
4. [推断] 触发是独立失败面:agentskills 渐进披露(常驻面仅 name 与 description)加 skill-creator 触发对(负例取近失)成熟,pass rate 基准有测量坑(真触发记 0),不引入。
5. [实证] Mem0 2026 起提取路径 ADD-only、显式 update 另走 API(总台直读官方 docs 验证);与 sources 只增不改同向,自动 UPDATE/DELETE 为负例。
6. [实证] 单仓纪律形两操作件(提交分层加路径级回滚)在三仓两例实证;agent 记忆库内嵌技能形(Letta MemFS)定为排除项。
7. [实证] 断言纪律实录:ai-ccoe con-01 六件中五件吻合、一件打回(sources 根残留 3 件),回执自证与盘上实态的差由总台独立复核抓出,打回重证走通。
8. [假设] 技能集大到描述触发不够用时才需向量 top-k 检索(Voyager 形);本轮无技能个数证据,不立项。
