# 汇报面:AI 回答与回执的受控中文

> 蒸馏自 ASD-STE100 中文家族实践(2026-10-13 吸收);与六节四十条同族互补:文档面规则冲突时上游规范 0.2 优先,汇报面以本页为准。适用:向用户交回执、报结果、给排查结论、请决定时。

## 一、结构律（结论先行）

- 第一句 = 结论或状态;不预热、不复述任务、不先叙事
- 汇报顺序:结论、关键证据、影响、后续
- 同类信息超三项用列表;对比信息用表格
- 有标题时动词开头;关键结论加粗

## 二、状态词表（汇报首词,十个）

| 状态词 | 义 | 必补内容 |
| --- | --- | --- |
| 已完成 | 全部做完 | 一句怎么验的 |
| 部分完成 | 做了一部分 | 剩余项列表 |
| 未开始 | 还没动 | 原因或时机 |
| 进行中 | 正在做 | 预计完成条件 |
| 已验证 | 做完且验过 | 验证方法与命令 |
| 未验证 | 做完没验 | 原因与影响 |
| 失败 | 没做成 | 失败点 |
| 跳过 | 主动不做 | 原因 |
| 阻塞 | 被卡住 | 卡点与所需输入 |
| 未确认 | 等人裁定 | 待裁点 |

- 状态词只用本表十词;不自造近义状态词(做好了、搞定了、应该行)

## 三、验证状态

- **已验证**写三件:方法、命令、输出摘要;引用具体数字(几条、多少行、哪个提交)
- **未验证**写两件:原因、影响(哪些结论因此打折)
- 与本仓六态纪律的呼应:事实性断言标六态([实证][推断][经验][记忆][假设][直觉]);汇报面的验证状态 = 六态的回复形,说结论必说证据等级
- 不写「应该没问题」「大概率没问题」;要么给验证,要么标未验证

## 四、询问律

- 首句 = 直接问题;不先铺垫
- 选项编号,每项一行:选项名、代价、后果
- 尾部留自由文本口(「都不选可直说」)
- 二选一以上必须给编号选项;不开放问「你觉得呢」

## 五、语言律（汇报面增量;文档面见六节四十条）

- 情态动词只用三词:**必须、不得、可以**;不用近义词(应当、务必、严禁、尽量、或许、可能、也许);技术不确定性写条件句(若 X 则 Y)或用状态词,不写或然副词。「不得」仅汇报面用;文档面按上游词表用「禁止」或「不要」
- 开头不用缓冲语(需要注意的是、请允许我、总的来说);直接进正题
- 不用比喻、成语、拟人(「数据库饿了」「打个补丁堵住枪眼」)
- 数字带单位;不用未量化词(大约、数量级、很多、不少)
- 主语不漂移:代词只指上一句对象(沿 2.8);连续两句换主语时重写名词

## 六、五模板（填空形）

**进度说明**:

```
进行中:<任务一句>。
已完成:<子项>;剩余:<子项>。
预计:<完成条件或时点>。
```

**结果汇报**:

```
已完成(已验证:<方法>):<结果一句>。
证据:<命令或文件引用>。
影响:<对后续的影响>。
```

**排查结论**:

```
<结论一句>(已验证 / 未验证)。
原因:<根因>。
修复:<动作;未修则写候裁>。
```

**请求决定**:

```
<问题一句>。
1. <选项> : <代价> : <后果>
2. <选项> : <代价> : <后果>
都不选可直说。
```

**多项总结**:

```
<总起一句>。
- <项一>:<状态词> <一句>
- <项二>:<状态词> <一句>
```

## 七、发前自检

1. 第一句是结论或状态?
2. 状态词用了表内十词?
3. 验证状态给了方法或原因?
4. 句长过限(操作句 30、描述句 40)?
5. 一句一事?
6. 情态词只三词?
7. 选项编号了?
8. 命令可复制(取用行原样)?
