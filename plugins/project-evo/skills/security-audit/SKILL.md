# 安全审计

找出违反真实信任边界的漏洞,然后给所有者提供源码证据、安全复现、优先级与最小有效修复。这是防御性的、源码优先的工作流。一个候选若说不出具体受影响的主体、资源或安全后果,就不是已确认的发现。

## 运行模式

本 skill 默认是指导模式。加载它不等于授权完整审计工作流或创建文件。

- **指导模式**:安全问题、聚焦审查、方法论、分诊或对特定发现的调查,只用本 skill 的相关部分。不要自动跑全部六个阶段、建输出目录或写审计产物。需要时可派聚焦 agent,它们把结果返回当前任务。
- **全量审计模式**:用户明确要求审计或渗透测试一个代码库、要求完整/全面/端到端安全审查、或要求报告产物时,才用完整工作流。跑全部六阶段并写下文定义的文件。

请求两种模式都可能时,先问一个聚焦问题,再创建文件或启动完整工作流。

## 平台术语

本 skill 与平台无关:

- **Parent(父协调者)** 是协调整次运行并持有共享状态的 agent。
- **Task 工具** 是平台的委派/子 agent 机制。
- **`research` agent** 是被委派的聚焦源码探查与事实验证 agent。
- **`general` agent** 是被委派的宽域调查与有界本地执行 agent。
- 标题里的 **`subagent_type:`** 指明该工作由这两种委派角色中的哪一种执行。

用平台的等价能力,保持角色、写隔离、提示词与独立性边界不变。

## 通用执行安全

以下规则在两种模式下都适用。源码检查只读。运行目标可控的构建、测试、进程、浏览器、模拟器、fuzzer 与夹具处理,只允许在提供以下全部控制的 OS 级沙箱内:

- 无外网;检查确需本地 client/server 流量时,只用隔离的 loopback 命名空间;
- 空环境,由显式允许清单填充安全取值,HOME、临时目录与缓存都在 scratch 本地;
- 目标与工具链只读,目标可控进程只能写进它被指派的 `scratch/` 目录;
- 显式的低 CPU、内存、进程、文件大小、磁盘与墙钟限制。

agent 在目标可控进程之外,构建必须在源码旁写入时,可在被指派的 `scratch/` 里做一次性源码副本。指导模式不留存目标可控文件。全量审计模式中,只有可信的父侧代码可按「写隔离」的程序,把最小非机密结果晋升进留存的 `artifacts/`。永远不要把留存输出目录(该 agent 自己的 `scratch/` 除外)、其他 agent 的目录、宿主家目录、凭据、socket 或共享服务暴露给目标代码。不安装依赖、不让构建拉取依赖。只用本地已有的工具与依赖。任何控制无法落实时,不执行目标代码:把缺失的沙箱能力报成 needs-validation 阻塞项,并给出安全的验证计划。

用假主体、假夹具、假密钥。不探测已部署端点、外部服务、共享基础设施、生产身份、其他用户数据或在线控制面。不对在线或共享进程做可用性测试、不发布产物、不改 release、不花付费 API 配额、不在确立缺陷所需的最小本地效果之外继续。决定性事实在源码与沙箱夹具之外时,报告为需要验证。

## 全量审计准备

全量审计模式在侦察前解析以下取值:

- **skill 目录**:含本 `SKILL.md` 的绝对目录。
- **目标**:受审仓的绝对根路径。
- **仓名**:来自目录或本地 Git remote 的稳定仓标识。
- **输出目录**:目标之外的新可写目录,默认 `~/security-audit-skill/<repo-name>/run-<N>`,`<N>` 为下一个未用整数。仅当用户显式选择且父协调者确认版本控制忽略整个目录时,才用目标内目录;否则停下请求外部路径。
- **源 ref**:受审 commit 与工作树是否 dirty。未审查的生成或修改文件不当作另一修订版。

### 写隔离

父协调者创建并独占写共享运行文件:

- `run-metadata.json`
- `architecture.md`
- `coverage-ledger.json`
- `findings.json`
- `REPORT.md`
- `FINDINGS-DETAIL.md`
- `NEEDS-VALIDATION.md`

每个猎手或验证者拿到 `<output-dir>/agents/<agent-id>/` 下唯一根目录,含独立的 `scratch/` 与 `artifacts/`。规范的 agent ID 匹配 `^[a-z0-9][a-z0-9_-]{0,63}$`,且不得等于 Windows 设备名(`con`、`prn`、`aux`、`nul`、`com1` 到 `com9`、`lpt1` 到 `lpt9`)。小写防大小写折叠冲突。agent 与所有目标可控进程只能写 `scratch/`;留存的 `artifacts/` 归父协调者所有,永不暴露给沙箱,只由可信父侧晋升代码写。agent 不得改共享文件、目标源码、留存产物或其他 agent 的目录。不得用 `/tmp` 或宿主家目录当可写兜底。

执行前,父协调者为 agent 的 `scratch/` 与 `artifacts/` 根打开并持有可信的、不可继承的目录描述符,并登记预期 scratch 相对产物文件的允许清单,加显式的单文件与累计字节上限。永不把这些描述符传给 agent 或沙箱。沙箱及其全部进程终止后,可信父侧代码逐个晋升每个允许清单内的文件:

1. 校验声明的相对路径:拒绝绝对、空、`.`、`..` 或符号链接组件。
2. 从持有的 scratch 根描述符出发,以 no-follow 目录相对操作逐级走每个父组件;永不按路径重开。
3. no-follow 且非阻塞地打开叶子。
4. 用 `fstat` 验证它是普通文件、链接数恰为一、且在登记的单文件与累计字节上限内。
5. 从该描述符读取时再次执行这些上限。
6. 精确复制已验证的大小,重复 `fstat`,身份、类型、链接数或大小有变即拒绝。
7. 目的地侧,从持有的 artifacts 根描述符出发,以 no-follow 目录相对操作走每个父组件;要求每个已存在组件是真目录,缺失目录以独占创建后再重开并 no-follow 验证。
8. 不跟随链接地独占创建叶子,验证打开的目的地是链接数恰为一的普通文件,并从已验证的源描述符复制,两侧都不按路径重开。
9. 非 POSIX 系统用等价的竞态安全 API。
10. 永不递归复制或 glob scratch、永不把压缩包解进 artifacts、永不打开或晋升符号链接、FIFO、socket、设备、目录、硬链接文件、变化中的文件、或超上限的文件。
11. 任何检查不可用、无法执行或失败时,丢弃该 scratch 条目;若它是决定性证据,保留 `needs_validation` 并写明确切晋升阻塞项。

`references/audit-hunting.md` 与 `references/audit-reporting.md` 以同一份围栏代码块携带本程序,供猎手与验证者提示词使用;其规则与本清单同序同义。

复现检查要记录命令、确切测试输入、沙箱限制、以及复现所需的允许清单内环境变量名与安全非机密取值。永不捕获或复制环境全量、继承变量、凭据值、认证状态或无关宿主路径。从空环境启动,而不是执行后再脱敏。

委派前,父协调者写 `run-metadata.json`,至少含 `run_id`、`repo`、`target`、`source_ref`、`profile`、`scope_paths`、`budget`(未设为 null)、`execution_policy: "sandboxed-source-and-local-only"`、选定的领域伴随文件、先前运行路径、共享文件属主、`run_status: "in_progress"`。事实变化时才更新元数据;候选状态归覆盖账本与 `findings.json`。

## 全量审计规划

本节的覆盖、先前运行、档位与预算要求仅适用于全量审计模式。

### 覆盖与先前运行

一遍跑不完。猎手开工前建确定性覆盖计划,每个 agent 结果后更新。`references/audit-recon.md` 定义稳定的覆盖单元,`references/audit-hunting.md` 定义覆盖批评者波次。账本只由父协调者更新。

存在先前运行时,规划本轮前读每个兼容的 `coverage-ledger.json` 与 `findings.json`:

1. 把相关现源码与每条先前记录逐单元比对。仅有先前源 ref 不证明路径未变。
2. 先前 `confirmed` 记录仅当其相关源码与条件未变、且证据仍满足现行契约时,才带入当前候选集。链接到一个 seeded 为 `planned` 的当前账本单元,保留其指纹,只把该携带的根因排除出猎手清单,并让携带记录走当前最终验证路径;复核它的阶段 3 验证者成为该单元的归属所有者并移入 `candidate`。
3. 先前 `confirmed` 记录的相关源码已变时,建当前 planned 复验单元。不把该记录放进猎手排除清单。仅当当前独立验证确立当前路径与结果时,它才保持 confirmed。
4. 先前 `needs_validation`、`deferred`、`blocked`、`out_of_scope` 与任何源码已变单元都是当前工作。仍是外因的 `needs_validation` 记录,仅当当前源码追踪已核查、且按指纹链接到一个当前 `planned` 单元(其验证者复核补齐归属与证据)时才可携带;记录保留未解阻塞项。这些先前状态永不压制当前单元。
5. 先前同源已覆盖单元可 informs 优先级,但在当前账本中保持可见。先前 `rejected` 记录只压制同 claim 未变的失败断言,不压制其单元的覆盖;证据有变即产生当前工作。
6. 读先前档位与范围。先前 `quick` 或 scoped 账本只贡献其记录到的证据与空缺,永不隐含「其余没问题」。

无先前账本时,在最终覆盖声明中说明。永不暗示一次运行穷尽目标。

### 运行档位与范围

全量审计准备时,从用户请求选档位,或按目标体量与风险提议。记进 `run-metadata.json`(`profile`、`scope_paths`)并在报告中声明。默认 `standard`。

- **`quick`**:小目标、重跑或快速第一眼的有限一遍。账本单元粗化为 暴露面 乘 边界 乘 攻击类(子系统用固定规范标识 `profile/quick/all-in-scope-subsystems`),恰好跑一个猎手波次加恰好一次最终覆盖批评,每个候选一名新验证者兼做候选验证与最终记录复核。不追加猎手波次:批评者接受的发现与再分派记为 `deferred`。
- **`standard`**:按本文执行。
- **`deep`**:高风险或大目标。账本单元按子系统与生命周期模式拆分,批评波次跑到干净通过,候选验证与最终记录复核保持分离的新 agent,`prior_covered_same_source` 单元给独立第二遍。

**范围运行** 审计子集:指名路径、单个子系统、单个伴随领域、或两个源 ref 之间的 diff。只为范围内暴露面 seed 账本单元,其余全部记 `out_of_scope`(绝不记 `covered`)。范围运行或 `quick` 运行必须自陈为部分覆盖。

档位改变广度与冗余,永不降低证据门槛。不允许省掉候选闸门、源码/本地执行边界、`needs_validation` 纪律、schema 校验、`confirmed` 记录的独立验证。

#### 成本预算

账本让花费可数:一个单元约等于一次猎手指派,一个存活候选按档位一到两次验证者指派。用户设预算(或父协调者为大目标提议)时,把 `budget` 记进 `run-metadata.json`,为全阶段 agent 调用次数上限。

启动任何侦察 agent 前执行严格预算闸门。预留四次基线侦察调用、`quick` 的一次波次后批评 或 `standard`/`deep` 的一次波次后加一次独立终局干净批评、至少一次验证者调用。每次额外调用前重过此闸门,才加聚焦侦察。请求的预算撑不起这个最小集时,不派任何 agent:请求更大预算、更窄范围或别的档位。请求不变时,置 `run_status: "incomplete"` 与 `incomplete_reason: "budget_cannot_fund_reconnaissance_and_reserves"`,并报告没有跑任何审计遍。

按以下顺序花费:

1. 侦察、每次波次后批评、独立的终局干净批评都计入 agent 调用。
2. **猎手前预留批评与验证。** `quick` 预留它的一次波次后终局批评。`standard`/`deep` 每个猎手波次前,预留一次紧随波次的批评加一次独立的终局干净批评。另按档位预留验证者成本(每预期候选约 1 到 2 个 agent;拿不准就按批评预留后余额的 30% 预留)。永不把猎手指派进任一预留。
3. 按优先级给单元派猎手,直到猎手额度用尽。波次后立刻花费预留的波次后批评;终局干净与验证预留保持不动。
4. 后续波次前,重新预留它的新波次后批评。剩余预算盖不住必需的批评调用与验证预留时,该波次不派猎手,其 planned 单元标 `deferred`(理由 `budget_cannot_reserve_critics_and_validation`),用保留的终局干净批评记录形成的空缺。

波次 1 前用 seeded 单元、隐含猎手数、强制批评调用、验证预留、剩余预算是否覆盖计划,更新侦察前估算。明显盖不住时直说,并提议更窄范围或更粗档位,而不是悄悄稀释证据。后续事实吃掉了必需的终局批评预留时,不派猎手,全部 planned 工作标 deferred,run 置 incomplete(理由 `critic_budget_exhausted`),不做完整覆盖声明。

严格总预算仍可能被意外庞大的候选集或需要额外独立验证者的阶段 5 实质替换超出。剩余预算验不完每个候选时,停止猎手,按指纹顺序在预算内验证候选,置 `run_status: "incomplete"` 加 `incomplete_reason: "validation_budget_exhausted"`。每个未验证指纹保持链接到一个带该未解理由的 `candidate` 账本单元。不把未验证候选放进 `findings.json`、不改标 `needs_validation`、不把 run 报成完整。阶段 6 仅当首节声明候选验证未完成并列出受影响指纹与单元时,才可产出部分报告。永不无声超出用户设的严格预算。

## 核心原则

### 要求边界与结果

每个候选,说清低信任主体、被接受的输入或动作、预期控制、被跨越的边界、受影响的主体或资源、具体可观察或所有者可观察的结果。不把缺失最佳实践、猜测的部署行为、泛型解析器崩溃或自影响抬升为安全发现。

### 用有界本地证据

静态分析确立源码路径。全部执行控制可用时,沙箱本地测试裁决行为:最小函数 harness、既有单元测试、小型解析器夹具、假租户集成测试、本地渲染配置、或有界的隔离 loopback 客户端。到错误返回值、未授权假记录、sanitizer 发现、策略差异或其他最小效果即止。不把本地检查扩到最小边界结果之外,不产出持久化、故障后或隐匿类材料。

### 尊重源码可见性

部署控制、代理行为、提供商设置、浏览器头、身份策略、broker ACL、打包与拓扑都是真实控制。它们被需要而仓里没有时,不假设存在也不假设不存在。用 `needs_validation` 附确切缺失事实与安全的所有者可观察或本地计划。

### 优先级与确定性分离

只有 `confirmed` 记录有严重级。可能性与影响必须反映已论证的条件与结果;总严重级不得超出已论证的影响。`needs_validation` 意味着一条具体的源码奠基的边界假设被阻塞,不是低置信的已确认漏洞,它没有严重级。

总严重级按以下锚点校准:

- **critical**:未认证行为者获得代码执行、全数据存储访问或任意账户接管。
- **high**:行为者完全击穿显式安全控制且有真实后果:认证绕过、跨租户读或写、影响其他用户的存储脚本执行、已认证代码执行、或对共享服务的未认证远程停机。
- **medium**:真实边界违犯但爆炸半径有限、前置条件不常见、或后果限于窄资源集。
- **low**:非机密内部信息暴露,或需持续投入换微小收益的效果。
- **informational**:已确认但影响极小的观察,主要作为更大发现的先决件。

high 与 medium 的判别:已论证结果是完全击穿了有真实后果动作的显式控制,还是只是削弱它?说不出具体伤害,严重级就低于感觉。

### 推荐最小有效源码修复

每个已确认发现,找出代码必须维护的不变量与在最可信决策点执行它的最窄源码改动。优先具体的仓相对改动与回归测试,而非泛型加固建议。审计描述修复;不改目标源码。

## 全量审计工作流

全量审计模式按序走全部六阶段:

1. **侦察**:用 `references/audit-recon.md` 摸源码、信任边界、本地构建路径、伴随选择、先前证据与初始确定性覆盖账本。
2. **覆盖账本驱动的猎手波次**:从账本派隔离猎手,用 `references/audit-hunting.md`、`references/audit-attack-classes.md` 与选定领域伴随文件收集结构化候选结果。
3. **候选验证**:归并指纹,按 `references/audit-reporting.md` 给每个候选一名全新源码验证者。
4. **结构化输出**:全部最终 `confirmed`、`needs_validation`、`rejected` 记录写入 `findings.json`;用 `scripts/report-schema.json` 与 `scripts/validate-findings.cjs` 校验它,用 `scripts/validate-coverage-ledger.cjs` 校验覆盖声明。
5. **独立记录复核**:用新 agent 复核最终源码断言,协调修正或状态变更。
6. **目标中立报告**:从最终记录导出 `REPORT.md`、`FINDINGS-DETAIL.md`、`NEEDS-VALIDATION.md`,不含在线探测指令。

以下两种终态恰居其一才结束运行:(a) 阶段 6 产物全部写出且两个校验器通过;或 (b) 记录 `run_status: "incomplete"` 附确切理由,且报告披露空缺。绝不中途停。

## 反模式

1. 把清单偏差当漏洞报。
2. 没有可达边界违犯的纵深防御建议。
3. 有界本地证据不足就做在线或共享环境测试。
4. 猜测源码中不存在的提供商、代理、浏览器、身份或部署行为。
5. 把同主体预期权限或自影响当跨边界结果。
6. 报告比观察效果更强的解析器或运行时效果。
7. 产出无法去重、无法验证的纯散文猎手结果。
8. 重复报告携带的同源先前 confirmed 记录,或把它们当锚定猎手的范例。
9. 给 `needs_validation` 记录标严重级。
10. 独立验证前写报告,或散文与 JSON 不一致。
