# 云与部署专题审计

> 本篇角色：仓库定义云身份、基础设施、容器、Kubernetes、服务网格、serverless 函数、边缘 worker、ingress、对象存储、托管服务或环境专属配置时，审计部署组件是否获得预期的身份、隔离、网络可达性、密钥与策略。

#### 何时使用本篇

仓库定义云身份、基础设施、容器、Kubernetes、服务网格、serverless 函数、边缘 worker、ingress、对象存储、托管服务或环境专属配置时使用本篇。该领域回答：部署后的组件是否获得预期的身份、隔离、网络可达性、密钥与策略。源码常表达意图而非线上事实，因此要区分「源码已证实的缺陷」与「需部署验证的事项」。

构建与晋升信任用 `audit-supply-chain.md`，HTTP 代理语义用 `audit-web-auth.md`，数据存储租户范围用 `audit-data-lifecycle.md`。

## 核心纪律（加入本领域每个 agent 提示词）

```
- 不要仅凭清单（manifest）推断线上暴露面。确立哪个环境消费它、哪些默认值或 overlay 修改它、该源码路径是否处于激活状态。
- 把每个工作负载的身份映射到具体操作与资源。仅当更低信任的输入能触达未授权操作时，宽泛策略才算发现。
- ingress、代理、服务网格、元数据服务与准入策略都是真实边界，但只有控制点的配置与挂载关系可见时才计入。
- 密钥引用不等于密钥泄露。必须存在更低信任的读取者、输出、产物、日志路径或不安全回退。
- 仓库内激活配置与本地渲染/策略验证用 `confirmed`；账户策略、网络挂载、运行时准入、托管元数据或需所有者观察的漂移用 `needs_validation`。
```

## 工作负载身份与 IAM 攻击类（subagent_type: `general`）

**工作负载身份越权**
工作负载、pod、函数、边缘 worker 或节点身份可操作超出其角色的租户、账户、资源或 API，且不可信请求或任务输入能选定该目标。审查云策略条件、资源模式、服务账号挂载、命名空间映射与回退凭据。

**跨账户或跨租户角色混淆**
角色假定（role assumption）、外部 ID（external ID）、令牌交换、工作负载联合（federation）或资源策略接受了未绑定预期源账户、受众、仓库、命名空间或工作负载的身份声明。需同时确立信任策略与调用方可控的声明。

**应用授权委托给云元数据**
应用信任调用方提供的身份头、标签、账户 ID 或资源元数据，却未验证其来自云控制平面或可信代理。云 IAM 与应用授权是两道独立检查。

## ingress、网络与控制平面攻击类（subagent_type: `general`）

**意外的服务或管理平面可达性**
某个 ingress、service、listener、安全组、负载均衡注解、端口映射或服务端绑定把 admin、debug、metrics、节点、控制平面或内部 API 暴露给更低信任的网络。仅缺失网络控制属 `needs_validation`；仓库可控的通往敏感 handler 的公网路由可判 `confirmed`。

**可信代理与网格身份绕过**
后端接受了来自预期 ingress/sidecar 之外的对端的转发身份、mTLS subject 或授权元数据，或备用端口与健康检查/legacy 路径绕过网格。验证头剥离、对端可达性，以及代理缺失时的 fail-open 行为。

**元数据与内部服务可达性**
不可信 URL、目标地址或协议选择触达实例/容器元数据、控制平面 socket 或携带工作负载凭据的内部 API。URL 解析与重定向处理在 `audit-attack-classes.md` 下追踪；本篇确立部署层网络、元数据版本与身份边界。

## 容器与编排攻击类（subagent_type: `general`）

**主机或控制平面能力暴露**
更低信任的工作负载可选定 privileged 模式、capabilities、主机命名空间、主机路径、设备挂载、容器运行时 socket，或越入节点/控制平面权限的服务账号令牌。单纯缺少 seccomp 或只读文件系统属加固；仅当可触达的操作跨越该边界才算发现。

**准入与策略路径不一致**
一条部署路径强制镜像身份、命名空间、资源、密钥或特权策略，另一条 controller、任务、升级、恢复或兼容性路径却不强制。确认替代路径与其产出的已部署对象。

**命名空间与标签信任混淆**
网络、准入、密钥或工作负载身份策略依赖更低信任主体可设置的标签、注解、名称或命名空间。对比「谁控制选择器」与「匹配授予什么权限」。

## 配置与密钥生命周期攻击类（subagent_type: `general`）

**安全控制优先级漂移**
开发值、chart 默认值、环境变量、命令行旗标、feature gate、sidecar 注入或分区域 overlay 在已部署环境中关闭认证、传输安全、租户范围或审计策略。为每个维护中的部署渲染最终配置，不要只看基础文件。

**密钥跨工作负载边界暴露**
密钥进入日志、崩溃报告、进程参数、共享环境、宽泛挂载卷、构建产物、服务发现，或另一工作负载/租户可读的 API。检查密钥类型与权限；公开端点或 key ID 不是凭据。

**凭据续期与故障回退**
挂载、刷新、轮换或吊销工作负载凭据失败，导致陈旧凭据持续有效，或应用退化为接受更低信任的身份模式。审查启动、就绪探针、重连与缓存客户端行为。

## 托管存储、事件与边缘攻击类（subagent_type: `general`）

**对象与签名 URL 策略混淆**
桶/容器策略、对象键、CDN origin 或签名 URL 未绑定主体、操作、对象命名空间、受众或过期时间。除读取外，还要审查列举/版本操作与写入路径。

**事件源身份混淆**
函数或 worker 把事件体字段当作源身份，却不验证提供方签名的信封、订阅/topic、账户、区域与重放状态。对比 push、pull、重试与死信路径。

**边缘/运行时边界错配**
边缘或 serverless 运行时假定的密钥、API、文件系统、隔离或租户策略与源站运行时不同，且回退到源站会改变权限或缓存行为。确认哪种配置选定哪条路径。

## 通用手法（贯穿上述各类）

- 渲染每个维护中的环境，做一张外部端口、工作负载身份、网络对端、挂载密钥与云资源的矩阵。差异必须有所有者或策略解释。
- 沿更低信任的请求、对象、标签或事件走进云策略。展示最终执行操作的工作负载凭据，以及本应约束它的条件。
- 对比常规部署、迁移、恢复、节点维护、故障切换与本地/模拟器路径。审查 mesh、admission、身份、密钥或策略服务不可用时的行为。

## 验证规则（报告本篇任何发现前适用）

1. 确立激活的源码路径与生效的部署对象；否则用 `needs_validation`，并写明缺少哪份渲染后的清单或所有者观察到的挂载。
2. 指明更低信任的调用方/工作负载、云或应用身份、可控选择器、受影响资源，以及未授权操作或泄露。
3. 在固定版本上核实提供商与编排器默认值。不要假设公网 IP、可触达的元数据服务、宽松防火墙或准入挂载缺失。
4. 本地验证可以渲染模板、评估策略、在隔离 fixture 中检查容器/用户命名空间，或用哑身份运行模拟器。不要探测线上端点或改动共享云资源。
5. 只有完整的激活源码链路加具体边界结果才返回 `confirmed`；否则返回 `needs_validation`，并写明所有者需补做的确切部署策略、身份挂载、overlay、网络或漂移观察。
