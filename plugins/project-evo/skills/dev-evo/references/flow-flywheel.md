# 多仓飞轮协作：herdr 会话治理协议

> 跨仓治理的操作协议:一个总台协调多个单仓工位,派单、回执、断言、吸收四步循环。沉淀自 2026-09-16 六仓四轮实证(对齐、标准态、终态、扩编与讨论)。

## 工位形态

- 每仓一个 herdr 工位（workspace 加 pane 加常驻 agent 会话）,总台自成工位;工位 agent 名或 pane ID 即派单地址
- 派单用 `herdr agent prompt`,回执用 `herdr agent read`;blocked 状态是等裁定,问用户不代答

## 派发协议

- **prompt 自包含**:任务清单逐件可判（过/缺/不适用）加标准权威路径加回执格式;接收方没有派发方的上下文
- 插队向 working 工位发单可以,但回执以 commit sha 加 diff 范围甄别,防混入在跑轮次
- 纯讨论轮（不改仓不提交）用于标准征求意见,结论按吸收即提炼回标准文本,不点名来源仓

## 回执纪律

- **对方陈述不作数**:commit sha 自取 `git log`、门禁自跑取退出码（落盘直跑,不接吞退出码管道）、CI 自取 `gh run` conclusion
- 断言带原文证据:说某文本「仍是旧口径」必须引读到的行,grep 反证优先于口头回执 [实证: 六仓轮中一次旧文误报被 grep 反证]
- 零改动回执合法,不强制造提交;不适用面一句裁定留痕即可

## 端点测试支撑

- 四平台矩阵（lan-win 加 lan-ubuntu 加 lan-linux 加 lan-mac）实机验收,各仓按需向总台要端点支撑;连接姿势与 mesh 分工见 env-platform.md 第十节
- 跨仓引用证据（如交叉岗抓平台门控项漏注）照常走回执纪律

## 吸收与纠错

- 每轮回执中的标准反馈当场分流:文案缺口直改、机制缺口进 ROADMAP 积压、不可逆裁定立 ADR
- 工位实踩（管道吃退出码、旧文缓存误读）提炼成纪律条目回写标准,复利即在此
