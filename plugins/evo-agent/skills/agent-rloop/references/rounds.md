# 轮次契约与派单回执坑

> 循环轮次的盘上稳态:三件套模板、状态档检查点、干预矩阵、跨机 s5 细则;四步协议条文在上级 SKILL.md,派单回执坑实录附文末。批 128 由 herdr-flywheel 的产物契约篇与派单坑面迁入。

## 统一标准路径

- 根 = 系统临时目录下固定名 `herdr-flywheel/`(本地底稿与写作面;跨工位传递信道走 s5 键空间,见文末跨机细则):bash 侧 `${TMPDIR:-/tmp}/herdr-flywheel/`;pwsh 侧 Windows 用 `$env:TEMP\herdr-flywheel\`,Linux 的 pwsh 无 TEMP 变量,回退 `/tmp` 与 bash 同 [实证: 2026-10-10 本机 /usr/bin/pwsh 实查]
- 每轮(轮次)一子目录,名 = 日期加主题短名(如 `2026-10-10-归属周知`),子目录即本轮交流总档;每笔交流一个单号(发起方自定短标识加两位序号,如 `fleet-01`),三件套如下;并行轮各笔各自成套,无共享文件冲突

| 文件 | 谁写 | 管什么 |
| --- | --- | --- |
| `<单号>-brief.md` | 发起方 | 发起笺:契约(任务清单、逐件验收判据),验收以此文件为基准 |
| `<单号>-state.md` | 接收方 | 状态档:agent 自报稳态,按检查点更新,状态检测看这里 |
| `<单号>-receipt.md` | 接收方 | 产物笺:逐件对账与证据,产物验收看这里 |

- **原子写**:先写 `<名>.md.tmp` 再改名落定,防对端读到半文(沿 lane 台账纪律)
- 两层账分清:本篇三件套管「这笔交流」;并行义务台账管「整轮还欠什么」(见 parallel.md),互不替代
- 临时目录不承诺长存:轮次收尾择要吸收进仓(证据与标准文本),档本体可弃

## 交流分型

| 型别 | 判据 | 文件化 |
| --- | --- | --- |
| 任务型 | 要产出、有验收判据(改仓、跑门禁、提交) | 三件套 |
| 委托型 | 委派核查、评审、调研,要结论回执 | 三件套 |
| 同步型 | 周知通报(归属、标准变更),要留痕确认 | brief 加 receipt;state 简记(已接后直接已交) |
| 讨论型 | 征求意见、纯交流,不落仓 | 不文件化,屏读加吸收 |

发起方不限总台:任何窗格 agent 都可发起任务、委托、同步。

## 状态档检查点

接收方按检查点自写,每点一次原子写:已接(brief 已读且无歧义;有歧义即回问不写已接)、在办(当前步骤、心跳时点)、候裁(等什么、等谁)、已交(receipt 路径)。缺项如实报「未记录」不猜不编;零改动完成合法,照走已交检查点,receipt 记零改动与一句理由。

## 干预矩阵(herdr 信号乘盘上稳态)

| herdr 实时态 | 盘上状态档 | 判读与动作 |
| --- | --- | --- |
| working | 在办 | 正常在跑,不干预 |
| idle 或 done | 在办 | 疑停摆:agent read 实查屏幕后再动,不盲催;goal 在册可 goal heal |
| working | 已交 | 在跑别的单,本单验收不受影响 |
| blocked | 候裁 | 等裁定:read 看 UI 问用户,不代答 |
| 任意 | 心跳久未动 | 停滞:按租约纪律处置(parallel.md) |

门控用信号、判定用稳态:派单时机门控用 agents to 内置门控 v2(TUI 实况判标);实时态看 agents view;完成与在办判定一律以状态档加产物笺对账。

## 跨机细则(传递信道 = s5)

- **传递信道 = s5 键空间**(`rounds/<YYYY-MM-DD>-<主题短名>/<单号>-{brief,state,receipt}.md` 形,见 evo-agent:agent-s5 naming):发起方写 brief 后 put 上键,prompt 只递键;接收方 get 到本地轮次目录落底稿,再走三件套纪律;state 与 receipt 每检查点 put 同步(同键覆盖终态形);实时进展 append 轮次流、发起方 tail 取;本机无 s5 二进制时退回 prompt 全文内联并记注(兜底形)
- 跨机派单与周知同样走键(prompt 只递指针);笺内写清远程机器路径在哪台机、怎么到达
- 断言方从远端键 get 回执对账;凭据与路径问题走 herdr 消息道问,不走 s5

## 与官方 herdr 口径的分野

herdr 官方面(--skill,现役引擎文档)对文件回执的口径是「仅兜底,初版派单不预设文件输出」;本协议在任务、委托、同步三型上升格为恒文件化(s5 键加本地底稿),分野有意为之,辖域内以本篇为准,讨论型仍守官方缺省。

## 派单回执坑实录(现象、根因、修法)

| 坑 | 现象与根因 | 修法 |
|---|---|---|
| send-text 不是派单 | pane send-text 仅投草稿不提交 | 正式派单恒走 agents to |
| 工位编号漂移 | 旧档编号与实况不符,凭记忆派单投错工位 | 派单前必 agents view 实查(机读 agents list) |
| agent 名被回收复用 | 名随退出释放可被复用,凭名 steer 投错对象 | steer 前对 session id:agent get 与台账记录比对,不一致停手诊断 |
| done 假象多源 | done 与提示被吞、冻结、modal 误分类同形;goal 型轮次间隙也读 done | done 不作完成判据;以验收判据与盘上记录对账 |
| TUI 未就绪悬输入框 | 新会话 send-text 悬在输入框不生效 | 先 pane wait-output 等就绪标志再派 |
| prompt --wait 提交即返 | 提交后首查落在 idle 窗即命中收束返回 | 两段式:先 wait --until working 开工探针,再独立收束 |
| 备用屏读不全 | 出屏行不进宿主回滚缓冲 | 兜底请对方落临时 md 回路径;三型已恒文件回执,坑面收窄到讨论型 |
| JSON 键名 status 误取 | 管道取 `['status']` 抛 KeyError,`&&` 链短路派单未发 | 管道取键恒 `agent_status`;门禁检查与派单分两条命令发 |
