# 标题与正文模板

> 发单前组装面的字段口径、截断与脱敏纪律、回执三态模板。

## 一、标题公式

`<工具名> <版本>:<症状一句话>`

- 错误码与异常名保原文,不改写不翻译
- 不带 [bug] 前缀:bug 分类由 label 承载

## 二、正文六段模板

````markdown
## 背景与环境

<一句背景;OS、shell、平台要点>

## 复现步骤

1. `<命令原文>`
2. <必要前置条件>

## 实际输出

```text
<报错原文:剥 ANSI 色码后粘贴;超约 60 行保首 20 尾 20,中段标「…截断 K 行…」>
```

## 期望行为

<一句话>

## 版本事实

- `<工具> --version` 输出:<原文>
- 相关依赖或运行时版本:<有则列,无则删行>

## 相关单

<去重命中的旧单或相关单链接;无则写「无」>
````

## 三、截断纪律

- 先剥 ANSI 色码,再截断;色码剥离不算改写
- 超约 60 行:保首 20 与尾 20,中段一行「…截断 K 行…」
- 原文不改写不翻译,截断必标注

## 四、脱敏纪律

- token、密钥、密码:换 `<redacted>`,且停下发流程先查泄露面(口径见 evo-codesec:secret-scan)
- 内网主机名、家目录路径:换 `<host>`、`<home>` 占位
- 报错里的私人信息:换占位;仓 owner 名可保

## 五、回执三态模板

- 已发:`已发 <issue URL>(查重:词 <搜索词>,search N 条加 list M 条,判定非重复依据一句)`
- 命中 open 未发:`未发,既有 open 单 <URL>(判定:同命令同错误码)`
- 未能发:`未能发(原因:非 GitHub 仓或权限不足或定位不到),建议 <动作>`
