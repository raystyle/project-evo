# 已知误区（pitfalls)

> 落地本体系时的已知坑。落地前预警；踩坑后对照补充（新坑先记这里，重复出现的升级为独立参考文件或目标项目 ADR）。

## P1:ADR 与 REQ 混淆

- **误读**:把需求写进 ADR,或把技术选型的 why 写进 REQ
- **正解**:ADR 管「为什么选这个」(不可逆技术选择);REQ 管「要做什么、验收什么」。判定:内容回答 why 进 ADR,回答 what 与验收进 REQ
- [经验]

## P2:手改生成物投影

- **误读**:API 投影(docs/api/、docs/aidoc/、etc/*.api.md)看着不顺手直接手改
- **正解**:投影全部由工具生成,手改下次生成即被覆盖;要改的是源码契约注释,再跑生成命令同 PR 提交
- [经验]

## P3:静默假设需求

- **误读**:没问清用户意图就按自己理解立 REQ、开工写码
- **正解**:新需求必须澄清后才登记;禁止静默假设。没有 REQ 编号的实现是黑实现,验收时无处对照
- [经验]

## P4:为凑结构建空文档

- **误读**:初始化时一次建全所有目录文件,大量空壳
- **正解**:最小集起步(AGENTS + adr + requirements),每个文件建立时必须有真实初始内容;guides/diary/research 无场景不建。空文档比没有文档更糟,读者不知道哪些能信
- [经验]

## P5:编号复用与跳号

- **误读**:文档删除后编号拿来复用;或编号跳着发
- **正解**:ADR/REQ/S 各接当前最大号;退役编号**不复用**;rejected REQ 留档不删。编号是引用锚点,复用等于历史引用全部指向错误内容
- [经验]

## P6:六态标记滥用

- **误读**:把没验证的写成 `[实证:]`;或全文没有一个标记;或 `[假设:]/[推断:]` 长期滞留不处置(「终身不行,亦遂终身不知」)
- **正解**:关键结论必标;没验证标 `[推断:]/[假设:]` 并写清怎么验证、`[记忆:]` 附复核点(五态为进入实证服务);收尾时中转态升实证、留 research 或注销;「实证滥用」与「猜测冒充结论」都是红线
- [经验]

## P7:问题留在对话里

- **误读**:踩坑、裁定、方案只发生在会话中,不落文档;下个会话重新踩
- **正解**:发现即落:裁定进 ADR/REQ,踩坑进 diary,流程提炼进 references,环境事实进 AGENTS 环境节;临时补丁要么归档要么删
- [经验]

## P8:implemented 不回填 trace

- **误读**:REQ 实现完就翻篇,trace 留空;或随手写个不存在的测试路径
- **正解**:implemented 必须回填可跑的 trace(测试路径或验收命令),封版前 must 全 implemented 且 trace 可执行;trace 悬空等于需求链断裂(check.py PE-07 抓)
- [经验]

## P9:双份并行(摘要层膨胀)

- **误读**:AGENTS 把每条规则的细则写全,与 references/ADR 双份并行,每次变更要同步两处,漏一处就漂移
- **正解**:AGENTS 只留一行摘要与命令,细则唯一权威在对应文档(摘要层铁律);意图路由膨胀超过一屏即重构下沉
- [经验]

## P10:写规范的文件自己违规

- **误读**:认为规范载体天然合规,不跑门禁
- **正解**:规范文件同样过机检;豁免态门禁全绿是假象,退出豁免才见真章
- [经验]

## P11:豁免清单乱退出

- **误读**:先删豁免行再清字,或改过几行的文件就退出豁免
- **正解**:**先逐文件验证零违规,再删豁免行,删后全仓复验**;只改过几行的文件属「存量另跑」圈,只有整文件重写才有资格退出
- [经验]

## P12:旧索引当重写底稿

- **误读**:重写 README 索引时以旧文件为底稿增删
- **正解**:以磁盘为唯一事实源逐目录全量比对;抄旧稿会带出转义错误与漏登记,靠目录列表对账才抓得回
- [经验]

## P13:PowerShell 批量改中文 md

- **误读**:用 PowerShell `Set-Content`/`-replace` 批量改中文 markdown(快、顺手)
- **正解**:**中文 md 一律用编辑工具逐处改**,PowerShell 管道批改会塌行/截断;确要批量先备份、改后断链与行数对账。二犯即升格为工作流
- [经验]

## P14:口径类裁决直接落码

- **误读**:分类名/口径这类「叫什么」的问题边写码边定
- **正解**:**口径题先出清单对齐再动代码**;命名口径属一次性对齐成本,先展示再落码
- [经验]

## P15:对环境想当然

- **误读**:假设 CI runner 预装了本地有的工具;工具性正则没验证就用
- **正解**:环境假设与正则都**先验证再用**(CI 门禁上岗前实跑一次);环境事实记 AGENTS 环境节,不靠记忆
- [经验]

## P16:CHANGELOG 记流水

- **误读**:每次小改动都往 CHANGELOG 加一条,越记越细
- **正解**:CHANGELOG 只留**版本级里程碑**(定位变更/发布/阶段完成/核心能力整体落地);日常流水归 diary
- [经验]

## P17:AGENTS 无限膨胀

- **误读**:规则越加越多,AGENTS 长成百科全书
- **正解**:目标 <60 行,超限即下沉(细则进 references/ADR,AGENTS 留一行摘要加指向);AGENTS 是合同不是手册
- [经验]

## P18:supersede 单边指

- **误读**:新 ADR 写了 supersedes 旧篇,旧篇的 superseded_by 忘了回填
- **正解**:替代必须双向互指,改完跑 check.py PE-06;单边指的「被替代」篇仍会被当成现行决策引用
- [经验]
