# 合取闸门与发布纪律

> 项目没有自动评分基准,不用均值闸门;接受谓词是三条合取,判官只核这三条,不打总分。蒸馏与提案可以批量跑,接受永远停在待审。

## 接受谓词(合取三条,缺一即拒)

1. **既有门禁无回归**:项目当前全部门禁(测试、检查、扫描)在候选标准集下仍绿;任何一条变红即拒
2. **点名义务翻转**:至少一条事先点名(loop.md 执行步登记)、当前标准盖不住的失败义务,在候选下变为通过;仅「没有回归」是中性改动,拒;门槛是「变好」,不是「不变坏」
3. **知识链接成立**:候选标准页链到至少一页有 sources 引文的 knowledge 模式页(layers.md 单向支撑硬规则的闸门化)

- 判据形态:不看均值看点名;均值会掩盖单题回归,已翻转为过的点名义务在候选下退回缺,或任一已绿门禁变红,即拒
- 证据形态:门禁退出码自取、义务翻转自跑验证、链接自验可达;单次随机会话不得当分数,验证轮按 backends.md 隔离跑
- `no_action`:证据不足的合法出口,不跑闸、不改标准集、照记流水

## 回滚与留痕

- 拒绝:标准集 reset 回基线提交;提案全文加 diff 由闸门追加进防重提页(knowledge,只增);流水记一行结论
- 接受:标准集 commit(消息记轮次与翻转的义务);流水与索引同步
- knowledge 在闸门前已提交,拒绝不回收:模式仍然成立,只是这一案没有过

## 发布纪律

- **标准面只收过闸产物**:operations 目录(技能安装路径)里只能有接受后的标准 skill;knowledge 页、被拒全文、no_action 记录可留可读,但不得出现在技能安装路径上,蒸馏文本不是标准 skill
- **无人值守只批蒸馏与提案**:夜跑可以积累模式页与待审提案,接受停在人裁,不自动发布
- 成品不点名外部仓库:标准 skill 正文自包含,信源细节留 sources 与研究档案

## 跨端转移

- 标准 SKILL.md 字节可拷(双端同形),但**转移不是发布**:拷入目标端后是未提交的一案,在目标端重过同一合取谓词(目标端门禁、目标端点名义务);失败即 reset 回转移前提交;目标端同名标准默认不覆盖,覆盖须显式裁定
- 不做「拷完立刻 commit」;不做「一端进化、另一端直接继承」:两端各自的门禁各自过
