# 信源存档与登记

> 报告的断言要可溯:信源分级、原件存档、完成登记三件义务。

## 一、信源分级与双源门禁

- **三级**:全文 > snippet > 标题级;未读全文的信源只作旁证并标注,不得单独支撑关键断言
- 关键断言双源核对;只有单源时标独立性折扣(如 `[实证: snippet;折扣]`)
- **一手优先**:事件类断言核到一手(当事方披露、原始 PDF),媒体报道只作传播面证据;核验增量常在一手全文
- **官方在线材料锁版本**:同一机构的正文 PDF、落地页与新闻稿口径可能漂移;存档记 last-modified 与 SHA256,引用数字带日期戳,口径位移本身可作分析点

## 二、原件存档

- 报告所据 PDF 与关键页面原件落目标仓 `sources/<报告短名>/`(与报告短名对应)
- 网络页存 `.md`,头部附原文 URL 与取回日期;镜像兜底件(archive 快照)标注镜像,不当一手原件
- 大件入库走 Git LFS:超 50MB 触发平台警告、超 100MB 硬拒;`.gitattributes` 提前 track 大件扩展名
- 报告与存档中的片段一律脱敏,禁止回显完整密钥或凭据

## 三、完成登记

报告推送后,在目标仓完成登记闭环:

| 登记处 | 内容 |
| --- | --- |
| INDEX(或等价索引) | 报告表登记一行:日期、短名、分类、一句话结论 |
| diary(或等价留痕) | 当天日记记报告钩子 |
| 需求/任务面 | 立项行状态流转(如 PRD/TODO/REQ),回填实施要点 |

- 接新研究先搜索引防重复;元研究与 methodology 改进回写规范,不落 reports
