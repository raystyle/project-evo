# 资源耗尽与可用性专题审计

> 本篇角色：不可信请求、消息、文件、租户状态或 agent 工作可能消耗 CPU、内存、磁盘、连接、worker 槽位、付费 API 或队列容量，或能使共享服务死锁/崩溃时，审计可从源码评审的可用性漏洞。

#### 何时使用本篇

不可信的请求、消息、文件、租户状态或 agent 工作可能消耗 CPU、内存、磁盘、连接数、worker 槽位、付费 API 或队列容量，或能使共享服务死锁/崩溃时使用本篇。本篇区分「源码可评审的可用性漏洞」与「一般性能问题」。绝不通过压测共享或线上服务来验证。

内存完整性缺陷用 `audit-memory-binary.md`，broker 投递逻辑用 `audit-protocols-rpc.md`。可触达的致命错误即使其解析器已在其他专题覆盖，只要共享影响成立仍归本篇。

## 核心纪律（加入本领域每个 agent 提示词）

```
- 必须有一条「输入到成本」路径、一个缺失的有效上界，以及对其他用户、共享服务、安全功能或运营方支出造成的影响。请求者自己进程内的自我限制不是服务漏洞。
- 缺少限流本身不够。在判定某路径无界前，检查 body/消息/文件上限、并发、队列、deadline、数据库约束、上游网关与租户配额。
- 不要运行压力、饱和或生产测试。使用渐近分析、小边界 fixture、mock 付费调用、严格本地资源限制与确定性取消测试。
- 说明攻击者成本、服务工作量、持续性、波及范围与恢复。单个有界输入造成超线性或持久的共享影响，与持续大量请求有本质区别。
- 源码可见的失界可安全演示时用 `confirmed`；上游上限、部署拓扑、autoscaling、付费配额或恢复行为在仓库外时用 `needs_validation`。
```

## 计算放大攻击类（subagent_type: `general`）

**超线性解析、匹配或求值**
很小的被接受输入驱动灾难性 regex 回溯、嵌套解析、递归校验、符号求值、图遍历、模板展开或对抗性 sort/hash 行为。推导被接受的深度/基数与复杂度，然后在本地演示一条有界的增长曲线。

**解压与表示放大**
压缩、稀疏、嵌套、别名或编码后的输入远超检查过的传输或文件大小而膨胀。在每次扩展之后、跨解析器阶段验证上限，包括归档、图片、字体、结构化文档与协议压缩表。

**数据库与下游查询放大**
小请求制造宽扫描、病态 join、扇出、无界排序/聚合或大量下游调用，因为查询深度、过滤基数、分页或展开字段没有上界。确认授权并非有意允许同样的资源范围。

## 资源累积攻击类（subagent_type: `general`）

**无界缓冲与基数累积**
body、乱序流、上传、会话、唯一缓存键、metrics 标签、日志字段、订阅或待处理任务在没有逐项与聚合上限的情况下累积。查找断连、超时、取消与部分解析时的清理与过期逻辑。

**文件描述符、句柄与临时资源泄漏**
畸形或被取消的工作错过清理，保留 socket、文件、数据库游标、timer、子进程、临时文件或对象引用。确认泄漏通过有界本地迭代重复出现，并影响共享池。

**取消后的脱管工作**
客户端超时、断连、取消任务或授权失败已返回控制权，但数据库、模型、网络或 worker 的工作仍在运行。逐层追踪取消与 deadline 传播。

## 配额与调度攻击类（subagent_type: `general`）

**认证前工作失衡**
昂贵的解析、key 查找、密码学运算、解压或外部请求发生在认证与最早的尺寸/速率闸门之前。对比请求者最小成本与共享服务成本，并检查上游限制。

**配额记账范围与重置缺口**
记账使用攻击者可影响的 IP、路由、租户、key 前缀、任务 ID 或其他维度，使一个 principal 的工作逃离其预算或消耗另一 principal 的配额。审查整数溢出、分布式竞态、重试、重连与账户切换。

**worker、池与优先级饥饿**
低优先级或攻击者控制的任务占住无关用户需要的共享锁、worker、数据库连接池、事件循环轮次或调度器优先级。要求存在绕过队列/并发公平性或超期占住槽位的路径。

## 故障与恢复攻击类（subagent_type: `general`）

**可触达的致命错误或死锁**
不可信输入在共享进程中触达 `panic`、abort、致命断言、未处理异常、进程退出、锁环或无限循环。确认 supervisor 范围，以及不可用的是单个 worker 还是整个服务。重启隔离 worker 可降低影响但不消除缺陷。

**重试风暴与 fail-open 放大**
超时、依赖错误、部分处理的消息或健康检查失败触发同步化或无界重试，没有 jitter、上限、熔断或去重。验证单个有界故障源能否制造持久的聚合工作。

**毒记录与队头阻塞**
一条畸形记录或消息在共享队列、分区、启动扫描、迁移或恢复循环的头部反复失败。审查跳过/隔离策略、offset，以及其他租户是否共享被阻塞单元。

**不安全恢复与容量回滚**
重启、恢复、回退或清理路径重建无界状态、无视当前配额，或恢复出立即重复失败的输入。恢复正确性是可用性的一部分。

## 通用手法（贯穿上述各类）

- 建立输入到资源表：最早被接受的尺寸/基数、认证前的工作量、下游扇出、持久性、共享池、上限与清理的归属方、恢复。
- 对比聚合上限与逐对象上限。一万个合法的单字节条目可能绕过逐消息上限，却耗尽租户级或进程级状态。
- 只在带严格 CPU/内存/时间限制与小幅增长点的隔离 fixture 中验证。mock 外部与付费调用；一旦缺失的上界或取消可观察即停止。

## 验证规则（报告本篇任何发现前适用）

1. 指明不可信输入、请求者工作量、服务放大或保留资源、共享波及半径与恢复。没有具体共享影响的「缺上限」只是加固。
2. 确认源码中没有任何上游、解析器、队列、租户或框架层上界能阻止该路径。部署侧未知的控制点要求 `needs_validation`。
3. 超线性行为要确立被接受的复杂度与有界的本地增长；泄漏要展示在理应清理之后仍可重复的保留；致命路径要识别进程/supervisor 隔离。
4. 按请求者工作量低、未认证可达、跨租户范围、持久性与恢复差排优先级；不要以可用性影响做验证。
5. 只有安全的本地证明加有意义的共享影响才返回 `confirmed`；否则返回 `needs_validation`，并写明所有者必须检查的确切上游上限、拓扑、配额或恢复观察。
