# 并行派单与义务图操作细化

> 上级 SKILL.md「并行派单与义务图」节的操作面。纪律源自外部多 agent 协作系统技术手册的核验对照(2026-09-17),本飞轮未整轮实测,首跑后回填实证标记。

## 义务台账

- 一行一义务,五字段:标识、验收判据(过/缺/不适用)、依赖(指向其他义务标识)、状态(欠/条件成立/已清账)、尝试列表(工位与路线)
- 台账只记「还欠什么」,不记「谁在干」:尝试信息只挂在尝试列表,工位会话消失不影响台账本体
- 台账落总台仓内轮次档,不落工位会话;各工位每轮收尾重读台账再定下一步,禁止依据开工时的旧图工作
- 全图清账判据:收尾按依赖闭包清点,任何一条依赖链上还有「欠」即整轮未完成;单工位局部过门禁不等于全图义务清账

## 条件归约派单写法

- 上层义务的派单 prompt 可以只要求「连接证明」:给出 A、B 的验收判据与 G 的合成规则,断言「A、B 成立则 G 成立」,不等待 A、B 完工
- 连接正确性与子结果正确性分开验收:连接证明过验收即记「条件成立」,A、B 各自清账后 G 才翻「已清账」
- 派单 prompt 写法沿用四步协议派单节:自包含、逐件可判、附标准权威路径与回执格式;条件归约只是在任务清单里显式写依赖与合成规则

## 租约与改派

- 每次派单带约定时限(租约);工位在时限内无心跳(无回执、无 commit)即视为失联,任务改派他位,不等死会话
- 已交证据(commit、门禁回执、失败记录)落仓不落工位:改派后新工位从仓内证据接续,不从零重跑
- 失败记录与成功记录同权保留:失败路线是依赖重评估与瓶颈判断的输入,不因改派丢弃

## 依赖重评估

- 上游义务的验收判据或产物变更时,逐下游触发三选一裁定:附兼容证据复用、重跑部分验证、作废重写;裁定与理由记进台账
- 禁止只改台账链接沿用旧断言:上游变更未经裁定,下游「已清账」状态一律视为待重评估
- 重评估范围按依赖闭包算,不按文件相邻关系算

## 瓶颈三判(扩容前)

- 独立任务不够:义务图关键路径上的串行义务占比高,加工位无用;先拆义务,或用条件归约把串行依赖改并行
- 验证资源不够:任务清账快、断言积压,扩的是总台复核与门禁吞吐,不是工位数
- 接口频繁变化致返工:依赖重评估高频触发;先冻结验收判据与接口(条件归约正是冻结手段),再谈扩容

## 任务与尝试分开记

- 尝试列表每条记五元:工位与路线标识、启动时点、租约时限、最新心跳(commit sha 或回执时点)、结局(在跑/过验收/失败/失联)
- 同一义务可挂多条尝试并行攻坚,互不排斥;失败尝试的路线与原因留档,是依赖重评估与瓶颈三判的输入(与租约节的失败记录同权保留同源)
- 先过验收记账:完成归属以验收判据甄别,第一个过验收的尝试记账;后到尝试的产物按旧版本处理,不追问在跑路线的中断责任
- 旧产物不覆盖完成态:旧版本产物可存档备查,不得覆盖已成立的完成状态;义务因依赖变化重开时翻待重评估,不沿用旧完成态(衔接依赖重评估节)

## 与四步协议映射

| 义务图纪律 | 四步协议落点 |
| --- | --- |
| 台账只记还欠什么 | 派单:任务清单逐件可判,升级为带依赖与状态的台账 |
| 条件归约先接线 | 派单:prompt 显式写依赖与合成规则;断言:连接与子结果分开验收 |
| 租约与改派 | 派单/回执:时限约定与失联改派;证据落仓不落工位 |
| 任务与尝试分开记 | 回执:完成归属以验收判据甄别,先过验收者记账,后到不覆盖 |
| 依赖变化必重评估 | 断言/吸收:上游变更触发下游三选一裁定 |
| 瓶颈三判 | 工位形态与带起:扩工位前的判据 |
