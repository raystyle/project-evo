# 发现核实与交叉复核

> AI review 的发现是线索不是结论;核实、分级、复核、交叉四步纪律。实证自 hst_rs code review 整案(2026-08-31,十五条发现)与五轮复核链。

## 一、逐条核实再修

- 十五条发现(高 5 / 中 7 / 低 3)中高严重度 5 条经逐条核实为 4 真 1 部分真 [实证]
- 每条核实后再分级处置:
  - **全修**(高 + 中):用户定调后当日切片闭环
  - **记档不做**(低):逐条给理由(extractor 层成本高于收益、schema 无第二版 YAGNI、口径一致)
  - **顺手并入**:修复主项时顺路消掉的小项

## 二、修复本身也要过复核

- 一轮修复(settle 自动化)引入或掩盖的四个真缺陷(等待语义、锁内等待、固定 tmp 名、吞 kill 失败)被同 agent 二轮抓出 [实证]
- 三轮换视角(grok 单路)再抓出二轮重构引入的死循环与布局缺口 [实证]
- 结论:**每轮修复可能引入新缺陷,轮次到 CONFIRM 为止**,全修不免二轮

## 三、多 agent 交叉互补

- codex 抓并发与协议边界、grok 抓行为语义与布局形态,视角互补不重复 [实证: 五轮链 codex、codex、grok、kimi、codex]
- 五轮链每轮抓出上一轮新引入的至少一个真缺陷,形态互补(并发/语义/时序/契约)
- 多 agent 编排器可用自举验证:oma 编排的 agent 给 oma 自身做 review

## 四、计划外发现照收

- review 之外的收获可能大于 review 本身:一轮整案顺带抓出三个计划外真雷(后台进程零控制台卡死、task id 撞号、路径归一化时序双身份)
- 实测冒烟比单测先抓出两个计划外缺陷:修复验收不只跑测试面

## 五、全量 review 走任务协议

- 整文件集的深 review 不走会话直发,走任务协议委派:**委派即产物**(发现清单落任务目录的产物文件)、**收件人模式即闭环**(后台收件)
- 会话直发留给快核与小批;两种规模的选择见 SKILL.md 形态节
