# herdr-dev - 开发模式:窗格布局与双闸门

> 一个开发工位的多窗格分工与交付闸门:布局定式(通用四窗格、PI 模式五窗格)、评审闸门加自省验收双闸门、任务分发 lane。派单、回执、断言、吸收四步协议与状态门控的唯一权威源在同插件 `herdr-flywheel`(跨仓模式);本 skill 是开发模式特化,不复述派单命令细节。

## 一、窗格布局定式

**通用四窗格(主窗同 tab 四格)**:

| 窗格 | 角色 | 委派面 |
| --- | --- | --- |
| 主开发格 | 主编程及调度委派(claude code) | 总台本体;编程、调度、发布 |
| 研究格 | 研究(grok 等) | 资料与选型检索派单 |
| review 格 | 评审(kimi、grok、codex 等) | 推送前评审闸门(本 skill 第二节) |
| 自省回归格 | 自省验收(codex;PI 项目用 pi 本体) | 清单式实测回归,逐项 过/缺 加证据 |

**PI 智能体开发模式特化五窗格**:自省位用被测产品自身(用被测产品验证产品自身);另开副窗 table 格做实战验收(长跑解题会话,与自省格是两个独立会话)。通用项目四窗格足够,自省位可由 codex 替代 [经验: 双仓实践提炼,用户裁定 2026-10-07]。

- **双闸门收批**:review CONFIRM 加自省验收全过,双绿才收;有 F 或缺,修后重推复审循环到零
- **先推后审**:评审只认已推送的树,派评审前 commit 加 push
- **自省与实战会话纪律**:自省格上下文近满(约八成)重启会话再派;实战格保持长会话,近满让自动压缩接管(压缩表现本身就是被测面),压缩后失能才重启并记档
- **重载铁律**:项目代码落地后自省与实战两格必重启会话重载(旧进程等于旧码),派验收前确认格上跑的是当前 HEAD
- **TUI 就绪探测**:新会话先 pane wait-output 等就绪标志再派;普通进程脚本 send-text 加 send-keys enter 两步起

## 二、评审闸门(请求 到 放行)

```text
评审请求(批次/基线/改动面/证据/门禁语句)
到 评审格逐行核 diff,产出发现
到 回执三态(F 必修 / G 建议 / CONFIRM)
到 工位修复并回执(逐条对照,采纳评审方实证)
到 二轮快核(修复本身也过复核)
到 终审放行后推 main
```

- 评审会话 = review 格里的常驻 agent(codex 等);cwd 两形态按评审范围裁定:跨仓收件用用户级 home,单仓专属用该仓 cwd
- 两种规模:**快核**(单提交或小批,评审请求直发会话)与**全量 code review**(整文件集,走任务协议:委派即产物落任务目录,收件人模式收件)
- 纪律:达成一致前不推 main;AI review 的发现逐条核实再修(高严重度也可能部分真);每轮修复可能引入新缺陷,轮次到 CONFIRM 为止
- 窗格挂位、检测带起、查看与对话历史检索见 `references/panes.md`

## 三、自省验收(清单式实测)

- 验收单逐项可判 过/缺,每项带证据;用被测产品自身跑(PI 项目)或 codex 跑回归(通用项目)
- 自省会话纪律与重载铁律见第一节;验收与评审并行双闸,互不替代

## 四、任务分发 lane 模型

一次分发多个实现任务给多 agent 并行产出(分支加 PR 收尾)时,lane = 每 task 一 git worktree 加独立分支加独立工位;细则见 `references/lane-dispatch.md`。核心三条:

- **lane 恒禁发布**:lane 不 push、不 merge、不开 PR;发布是总台验收后的独占动作,只做可加可逆的事
- **状态台账唯一真相**:run 级 state 文件原子写(.tmp 加 mv),每轮 sweep 开头重读(抗会话压缩);探针按契约报六字段(session、turn_state、used_pct、compactions、mtime、probe),缺字段报 null 不猜;盘上记录优先,屏幕是回退
- **身份核验**:agent 名退出即释放可被复用,steer 前对 session id;done 态与吞单、冻结、轮次间隙同形,完成以验收判据为准;lane 求助铃先答后催
